# Harmony asynchronous menu-item candidate — October 15, 2026

`PE_MENU_ITEMS_ASYNC=1` selects an experimental guest `MENUITEMS` path. The default remains the existing synchronous handler. The candidate does not change `MENUPICK`, host menu prefetch timing, focus acknowledgement, or normal window raise/move behavior. It was compiled in isolation and subsequently live-tested in the owned Tiger clone; the original installed Agent was not overwritten.

The async path uses one persistent serialized worker and a fixed queue of at most 16 pending `(pid, path, session, epoch)` jobs, plus at most one active AX query. Duplicate active or queued keys are suppressed. When the queue is full, the oldest queued request is evicted; opening that menu again can request it. The worker performs the existing `PECopyMenuElement` and recursive `PEAppendMenuItems` AX reads and builds the same payload. It does not call Carbon or write to the socket.

Before each AX read, the worker asks the main thread for a fresh Process Manager front-PID and session/epoch snapshot. The main callback prunes queued work for prior foreground PIDs and refuses stale jobs before AX begins. `reportFocused` also updates that foreground snapshot as the guest's front app changes. After AX returns, the main publication callback repeats the current front/session/epoch check and sends `MENUITEMS` only if the request is still current. Disconnect, reconnect, and Harmony transitions invalidate pending and active tokens, so old completions are dropped. The main thread never waits for the worker; the worker does wait for the brief main-thread gates. A front-app switch immediately after the pre-read check remains a race: an already-entered Accessibility IPC cannot be cancelled, but its stale result cannot be published.

`guest/tools/pemenuitemsasynccheck.m` passed on the trusted PPC host against the actual Mac OS X 10.4u SDK. It verifies the 16-entry bound and oldest eviction, foreground queue pruning before dequeue, active/pending deduplication, readiness while a job is active, wrong-front/session/epoch rejection, disconnect/Harmony invalidation, fresh-session acceptance, and retry after completion. It is a state fixture, not an end-to-end Accessibility/menu UI test. The agent build emitted only the existing warning that `PEAgent` may not respond to `send:text:` from `sendDockApps`.
