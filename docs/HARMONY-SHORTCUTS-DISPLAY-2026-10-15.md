## New implementation

- A fresh two-screen VM launch on a host with fewer than two available displays warns before boot and saves a one-screen configuration. Cancel preserves the two-screen setting and does not boot. Running/adopted VMs are not reconfigured. A sleeping two-screen VM instead warns and resumes both screens together; removing a graphics device would invalidate its saved hardware state and risk open work.
- The PowerEmu Dock menu has one Guest App Shortcuts entry instead of installed/running-app and per-app launcher lists. The Machine menu also opens the manager.
- The searchable, scrollable manager uses the existing Tools installed-app list; it does not require another guest utility. Selection is per VM package and exact guest app path, saved atomically with owner-only permissions. Selected app representatives appear while that VM runs, including outside Harmony. Selecting a shortcut does not open its guest app.
- Session icon clicks route to their owning PowerEmu session and verify a fresh guest app list before opening the exact selected app. Another installed/running host cannot receive the click through a generic URL handler. Normal-mode shutdown tears down the correct VM's representatives.
- Per-app contextual menus retain creation of permanent launchers for explicit Keep in Dock/cold-start use. No macOS Dock preferences are rewritten. Signed executable copies remain unchanged; helper protocol is version 2.
- Unopened selected apps initially use a generic icon. Running selected apps can supply their actual guest icon. Existing transient tiles are suppressed when their known PID/path matches a selected shortcut.

## Test 4 Tools reinstall failure and repair

User testing found Harmony unavailable after reinstalling the bundled Tools. The actual installed Agent was mode 0644 and absent from the process list. The copied candidate Agent artifact had been downloaded with mode 0644; `copy2` preserved that mode inside the ISO. Earlier direct-binary live QA explicitly set mode 0755 on upload, so it did not validate this packaging property and missed the failure.

The live user guest was repaired narrowly: restore mode 0755 on its installed Agent executable and launch that existing app. Its exact binary remained unchanged, and Agent PID 233 appeared. CUA then entered Harmony, found three guest window proxies and verified a rendered guest Finder window. No VM restart, guest work shutdown, or change to a running host bundle was required.

Prevention: the candidate-disc stager sets the known Agent executable to 0755. `scripts/check-tools-executables.sh` validates all four required payload executables, and normal `make-tools-disc.sh` invokes it. The regression fixture rejects the exact 0644-Agent failure and a missing installer, and accepts a complete executable payload. The Tiger installer also checks both source and staged Agent executability before stopping or replacing working Tools. A separate corrected build will retain the exact tested host/backend and replace only the Tools disc. The corrected ISO must be mounted read-only and its actual payload checked before delivery; source-tree permission checks alone are insufficient.

Corrected delivery: `build/staging-hourly/PowerEmu Harmony Shortcuts Test 4.1.app`. All four actual payload executables on its read-only mounted ISO are mode 0755; the staged and mounted Agent bytes match. The new installer executable was compiled successfully on the trusted PPC host using gcc-4.0/10.4u.
