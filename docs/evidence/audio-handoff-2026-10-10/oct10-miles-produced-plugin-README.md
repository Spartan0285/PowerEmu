# Bounded produced-chunk diagnostic, not a playback change

Artifacts: `oct10-miles-produced-plugin.c/.dylib`, sanitizer fixture `oct10-miles-produced-plugin-test.py`, control utility `oct10-produced-control.py`. Existing callback observer is preserved. Candidate is signed by the same Developer ID, with the backend's bundled GLib/gettext paths. Default disabled install registers nothing or allocates no capture buffers; machine-none loader check passed. No production source changed.

## What is captured

At verified SS_fill entry retain exact driver and destination, restored caller SP/LR and entry CPU. At its paired verified blr instruction hook, read 1,024 bytes from the saved destination. Pairing crosses CPU migration. Duplicate SP/LR and overlapping active destinations reject. A nonblocking atomic try-guard never waits; contention rejects coverage. Per-CPU guest-read scratch reserves/page-touches 1,024 bytes before execution; no resizing beyond capacity, hot-path filesystem operations, guest writes, source-pointer inference or new HAL client. The driver+0xe6 chunk-byte field must equal1,024 on every entry. Current driver, code/TOC and RAM ranges are external same-run validation gates.

Global preallocated capacity16,384 chunks (~17 MiB), plus the existing bounded register event buffers. At256 stereo16 frames perchunk this covers95.1 seconds; use **at most60 seconds**, not120. Arm boundaries that split calls are rejected as unmatched/unfinished. Closed windows execute no guest memory/register reads. Format of produced bytes is not assumed: independent current SoundHeader/driver contract is mandatory before decoding.

Chunk ABI1,088 bytes, native little-endian metadata: u64 return-hook_ns, entry_ns, SP, LR; u32 driver,destination,returnCPU,entryCPU; u64 serial,snapshot_end_ns;1,024 payloadbytes. Timestamp interval brackets the read; this is bytes observed at the return hook, not an instantaneous/coherent atomic buffer snapshot. Serial is invocation order, not queued/presentation order. Callback/fill register events remain available for reconstructing eight-chunk batches. Guest virtual destinations are not physical DMA addresses.

## Fresh setup and immutable publication

Do not use historical driver/stack/buffer pointers as plugin args. Before boot create a fresh exact32-byte0600 regular control file, owned by currentUID, using `oct10-produced-control.py create PATH`. Loader rejects symlinks, wrong size/owner/mode, or already-published state.

Stage plugin with `enabled=1,produced-chunks=1,control=PATH,sites=FRESH_VERIFIED_MANIFEST,out=PREFIX,arm-after-sec=DELAY,window-sec=60`. No TOC/driver/range args needed in control mode. Site manifest must describe exact current mapped trusted Miles code, with callback+fill IDs0/1. Same-run code mapping/manifest must be verified before arming; a game restart invalidates the whole setup.

Before the arm window, verify current owned emulator and actual Warcraft PID, copied-PEF fullcode/TVector/TOC, fresh walked active driver and negotiated SoundManager format. Use current vmmap to establish **one actually readable RAM malloc extent** containing both destination buffers; do not take min/max across holes. Verify callback stack RAM extent from actual thread/register context. Then QMP-stop ownedVM and wait for a successful paused status response. Publish one immutable config with ready last, then resume. Do not publish merely on the initial QMP greeting: plugin install may not yet have run. The utility requires JSON assertions owned_vm_paused,same_run_identity_verified,live_code_match,stable_format plus integer toc,driver,dest_lo,dest_hi,stack_lo,stack_hi; these assertions must reflect actual retained checks, not guesses. Publication JSON retains full config/hash.

Control ABI32 bytes: eight little-endian u32 fields ready,version,toc,driver,dest_lo,dest_hi,stack_lo,stack_hi. Initial allzero; version1; ready0x50454d31 written last once. Plugin latches once in the armed window, checks immutable publication each hook, rejects absent/changed config. Do not modify/truncate/reuse the controlfile after publication. An unlatched/config-skipped capture is not clean evidence.

## Validation and memory visibility

Sanitizer fixture covers migrated pairing, exact bytes, duplicate/overlap/read failure/overflow/unfinished, control size/mode/symlink/ready/mutation rejection. Actual existing signed backend ran tiny no-disk PPC7400/mac99 code: each function writes256 words with an incremented value before blr. Static fixture retained369 uniform strictly incremented chunks; paused immutable-control fixture retained373, no read/pair/drop/unfinished/config errors and successful flush. This proves ordinary RAM post-store visibility at this backend's hook for this fixture, not immunity to concurrent game writes. The API header warns no generic pending-write flush guarantee; callbacks run pre-instruction, but preceding stores in the tested function were visible. Do not claim exact mix stage from one concurrently modified snapshot.

Mandatory stopped artifacts: `.events/.json`, `.chunks/.chunks.json`, `.config.json`, `.produced-flush.json`. Reject missing/nonempty coverage, event/PCM count mismatch, any drops/read/register/opcode/pair/config failures, unmatched/unfinished calls, changed identity/format, missing final all_outputs_ok receipt, or failed stopped flush. Independent validator `oct10-validate-produced-chunks.py` checks pairing/counts and must also require control receipt/identity gates. Successful C fixtures or callbacks do not score Warcraft quality. Native source must independently qualify and observer-off counterpart remains necessary. No waveform concatenation across unknown queue order or time warping.
