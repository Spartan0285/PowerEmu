# Harmony asynchronous focus candidate — October 15, 2026

`PE_FOCUS_ASYNC=1` selects an experimental `FOCUSWINDOW` path in `guest/src/PEAgent.m`; the default remains the existing synchronous path. This candidate does not change normal `RAISE` or `MOVE` handling and has not been installed into the guest.

The optional path uses one long-lived serialized focus worker and `NSConditionLock` state with one replaceable pending job. Each job snapshots window id, host sequence, connection session, Harmony epoch, and the `raiseBringsAppForward` mode. The worker performs AX target lookup, minimized checks, raise, focused-window/sheet validation, and retry delays. Carbon front-process reads, `SetFrontProcess*`, socket writes, and `FOCUSED` reporting stay on main. The main thread never waits for the AX worker; only the worker waits for main-thread callbacks. Main-thread activation and final acknowledgement both recheck the immutable job against current session, epoch, and sequence.

With `PE_FOCUS_ASYNC=1`, the menu portion of `reportFocused` no longer performs AX on main. A separate serialized menu worker has one replaceable pending PID/session/epoch/generation request. It builds the existing `MENUS` payload using the same AX menu-bar, children, and title reads; the main-thread callback sends it only when the request generation, guest session/Harmony epoch, and current front PID still match. Repeated window reports do not enqueue duplicates while the same PID is outstanding, and unsuccessful empty-menu reads are retried no more than once per two seconds. The environment flag unset keeps the old synchronous menu-report path. No socket or Carbon calls occur on the menu worker.

Disconnect, reconnect, and Harmony transitions invalidate outstanding jobs and pending work. A stale completion cannot activate a window or send `FOCUSREADY`. Once an Accessibility call is already executing, it cannot be canceled; the worker checks freshness after it returns and before any later activation or acknowledgement. The worker retains the exact AX element for the request lifetime, but revalidates the current CGS rectangle size and CGS-owner-to-PID mapping during activation and every retry. A closed, resized, or reused window id fails closed. Lease destruction releases the retained AX reference on success, failure, and stale cancellation paths.

`guest/tools/pefocusasynccheck.m` is a bounded PPC state/lifecycle fixture. It passed on the trusted PPC build host: pending coalescing and mode snapshot, a blocked fake worker while the main run loop ticks, disconnect/reconnect/Harmony-exit/sequence invalidation, minimized/sheet/focus/geometry/target no-ack gates, final front/owner/geometry validation, menu PID coalescing/replacement/stale-result suppression, and lease retention/release for stale and completed work. This fixture exercises the production state and lease primitives plus a fake blocked worker; it is not an end-to-end AX focus or menu test. The PPC agent and fixture compiled against the actual Mac OS X 10.4u SDK. The fixture emits compiler warnings about the production file's existing `send:text:` declaration when compiled standalone; no new source compile error was observed.

The candidate agent binary is `build/harmony-focus-async-candidate/PowerEmuAgent-async-candidate.ppc` (SHA-256 `87992684ec8a169423459846b288bf6265d038485e3ef7daaf8044e3d505af6e`). Keep `PE_FOCUS_ASYNC` unset until parent review and a safe live pending-input test.

### First matched live trial (parent-owned clone, October 15)

The parent ran a rapid 20-cycle CUA sweep against the same candidate binary with `PE_FOCUS_ASYNC` off, then on, then off. Initial control: 7 completed ACKs, median 357.536 ms, 10 superseded. Async: 4 completed, median 445.781 ms, 12 superseded. Return control: 4 completed, median 449.212 ms, 12 superseded. All recorded drops were zero. The different completion counts mean the medians are selection-biased and do not establish a performance change; this trial showed no reliable gain. A guest Save Sheet appeared and Cancel worked. CUA `typeText` visibly repeated characters, so that tool artifact is not attributed to the guest candidate. The temporary clone was stopped before its guard, its original agent MD5/PID were restored, and the async flag remains off. No promotion is justified.

## Review points

- Carbon `GetFrontProcess` / `GetProcessPID` and all `SetFrontProcess*` calls in the optional path run on the main thread; the Carbon thread contract is not assumed. The final acknowledgement rechecks front PID, CGS geometry, and owner on main after AX verification; a focus switch immediately after this check remains an unavoidable small check-to-send race.
- `performSelectorOnMainThread:...waitUntilDone:YES` can leave the one worker waiting if the app main loop is shutting down, but it does not block the main loop. A worker blocked inside AX IPC likewise cannot be canceled; it prevents later jobs from running until that call returns, while the pending slot remains bounded and replaceable.
- The exact AX element is retained only while its serialized job is active. Geometry and owner are revalidated so a closed or resized window cannot pass the final acknowledgement checks, but a stale in-flight `AXUIElementPerformAction` may still complete before the worker can observe cancellation.
